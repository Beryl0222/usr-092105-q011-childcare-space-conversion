# 老城区托育空间改造验收系统

面向老城区既有建筑改造为托育空间的跨部门验收台账。事件溯源实现，解决开放日暴露的三类问题：

- **午睡区仍在整改，招生页却按整栋建筑面积公布满额** —— 容量只能按“当前获准开放、可计容量的分区室内面积”折算；缺陷分区必须排除。
- **设计通过、施工完成、允许收托被混为一个“已完工”** —— 三者是三道独立事件/闸门，缺一道都不允许开园。
- **场地只剩两年使用权，长期班退出无人负责** —— 期限登记在案，长期班招生按剩余期限自动限制；到期前 180 天必须形成含设施、押金、儿童安置、恢复责任的三方签署退出方案。

## 事件契约（沿用底座四聚合，不新增）

| 聚合 | 承载事实 |
| --- | --- |
| `property_term` | 产权期限、原用途、邻里约定、共享时段、退出方案、交还恢复 |
| `design_revision` | 设计版次、设计通过、施工完成、材料检测、消防/卫生意见 |
| `inspection_finding` | 检查缺陷、派单整改、复验、分区验收 |
| `opening_decision` | 全园/局部开园决定、备案容量、证据、限制条件 |

事件类型共 16 种，见 `contracts/domain.schema.json`。事件由 `event_id` 唯一标识；重试必须沿用原标识；同一聚合流 `version` 从 1 连续递增。

## 关键规则（均在 `src/domain.js`，由测试锁定）

1. **三道闸门分离**：`DESIGN_APPROVED`（设计通过）不推导 `CONSTRUCTION_COMPLETED`（施工完成），两者都不推导 `OPENING_DECIDED`（允许收托）；被取代的旧版次不能补审批、补报完工。
2. **图纸修订触发重做**：新 `DESIGN_SUBMITTED` 的 `affected_zone_ids` 列出受影响分区，这些分区上旧版次的材料检测、消防意见、卫生意见、缺陷、分区验收**按分区作废**（意见按分区失效，未触及分区继续有效），`checksRequiringRedo()` 给出重做清单；随修订作废的缺陷不再受理整改，须重新检查立项。
3. **缺陷分级闭环**：`critical/major` 未整改不得开放；整改后必须补录“验收记录”复验证据，分区验收才成立；`minor` 缺陷可在列明明确条件、物理隔离并经两方签署后局部开放。
4. **局部开放**：`mode=PARTIAL` 必须逐一列明开放分区与排除分区、开放条件、隔离措施、两方签署、现场证据与限制条件；有未闭环严重缺陷或材料不合格的分区必须排除。
5. **意见时效**：消防/卫生意见书带 `issued_on`、`valid_until`；过期、结论不合格、对该分区已随修订作废的意见，开园命令一律拒绝引用（错误信息明确为“过期意见不得重新引用”）；意见书附带条件必须写入开园限制。
6. **备案容量**：`capacity_filed` 必须等于获准分区折算值——可计容量分区室内面积 ÷ 3 ㎡/人；多功能厅等共享区域按每周托育专用小时/50 小时折算；整栋建筑面积只登记、不折算；保育人员配比（默认 1:7）不足同样拒绝。
7. **招生页投影**：`enrollmentPage()` 是对外唯一容量口径——无有效开园决定/依据失效/场地交还时容量一律为 0；图纸修订触及已开放分区时，容量仅按未受波及分区重算并公示暂停分区。
8. **期限与退出**：开园有效期不得超过使用权到期日；剩余不足两年/一年自动生成对应长期班停招限制且必须写入决定；到期前 180 天总览提示退出方案缺失；`EXIT_PLAN_FORMED` 必须逐项写明设施、押金、儿童安置、恢复责任并由产权单位、托育机构、街道三方签署；恢复未验收不得登记 `SITE_HANDED_BACK`。

## 目录

- `contracts/domain.schema.json` — 16 类事件信封与 payload 契约。
- `src/validator.js` — 信封与事件流校验（类型-聚合配对、event_id、version、时间格式）。
- `src/domain.js` — 事件回放、规则引擎、命令入口 `SiteFile`、招生页投影 `enrollmentPage`、总览 `siteOverview`、重做清单 `checksRequiringRedo`。
- `src/scenario.js` — 中文联调场景“槐荫里社区托育点”：午睡区 major 缺陷整改中、R2 图纸修订、共享多功能厅、产权剩约两年。
- `src/report.js` — 任意日期的状态总览 CLI。
- `data/sample.json` — 由场景生成的 27 条事件流样例。
- `tests/` — 信封契约测试 8 项 + 业务规则测试 20 项。

## 本地使用

```bash
npm test                 # 运行全部 28 项测试
node src/report.js 2026-10-05   # 查看指定日期的站点总览与招生页投影
```

报告样例（2026-10-05）：午睡区未验收且不开放、FD-NAP-02 整改中；活动室/就餐区/多功能厅开放；招生页备案容量 **35 人**（非整栋 320㎡ 折算）；R2 重做清单精确到午睡区的材料、消防、卫生、缺陷复检、分区验收五项。
